# Release decisions and independent Windows testing

2026-10-28. Development candidates only; no public release, purchase or infrastructure activation. Phase 5.2 excludes Spline from the verified reduced artifact, but native source/object/relinking review remains a release gate.

Owner decisions requiring approval:

1. **License/name:** Apache-2.0 recommended, MIT also compatible with the current architecture; choose a public name and legal owner/contact. Neither choice clears bundled dependencies. Resolve `LICENSE_REVIEW.md` first.
2. **Signing:** consider SignPath Foundation only after all components satisfy its [OSS conditions](https://signpath.org/terms); eligibility and acceptance are not guaranteed, and its certificate uses SignPath as publisher. Otherwise owner selects a supported certificate/service and budget. No paid account, certificate, trust root or purchase is configured.
3. **Publishing:** select owner-controlled repository/HTTPS release host, publisher identity, release channel and support/security contacts. GitHub Releases is a possible host, not yet configured. Approve private signing-key custody and recovery before any signed update feed. Existing offline Ed25519 verification does not constitute an updater.
4. **Independent test environment:** provide a licensed clean Windows x64 guest/device, or approve installation of a hypervisor and an appropriate evaluation image under its terms. These can require administrator changes, downloads, disk space and reboot; none was performed implicitly. No paid VM needed if suitable owner hardware/licensing exists.

Current host: Windows 11 Home Single Language build 26300. CIM reports `HypervisorPresent: true`; this alone does not provide an independent guest. No independent Windows guest or detected guest-management command is available. The earlier no-hypervisor statement was corrected after native CIM inspection. Fresh profiles and a restricted PATH remain host tests. [Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/) requires supported editions such as Pro/Enterprise/Education; do not install an unsupported Home workaround. A [Windows Enterprise evaluation](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise) is a possible time-limited test image subject to eligibility/license terms, not a production license. A normal hosted Windows CI runner includes development tools and is not clean-machine evidence.

Required independent matrix: record OS/build/tools inventory; disable shared development folders; copy only the verified installer; standard-user fresh install and Start-menu launch; first-use provider setup/removal with offline placeholders; native folder picker; preview/inspection/export; crash/restart; 0.3/0.4/0.5 upgrades and registry/files rollback; interrupted install recovery; uninstall with user data retained. Verify application operation without global Node/npm/Git or downloaded Playwright browser. Project toolchains remain separate prerequisites. Capture guest snapshots/logs and do not relabel host evidence.

Manual accessibility gate: human Narrator or NVDA reading/order/announcements in welcome, provider/key errors, routing, permission prompts, chat progress/completion, diffs/tests, preview diagnostics and native folder dialogs; keyboard-only long-session review, high contrast and OS scaling. Automated axe and Chromium AX-tree evidence does not demonstrate speech output or native-dialog usability.

Phase 5.2 read-only environment research: the former Microsoft developer VM-download URL currently redirects to its development-environment guide, so it does not establish an available clean image. Enterprise evaluation is a possible owner-approved image, subject to its current terms, on an existing independent guest/device. GitHub-hosted Windows runners offer ephemeral machines but include development software; useful for supplemental CI, insufficient for the clean-machine gate. No runner workflow, OS image download, hypervisor installation, feature change or cloud allocation was initiated. Preferred next step: owner-provided already-licensed spare Windows device/guest; otherwise approve a specific environment/terms before setup. A true OS-cold benchmark needs a controlled reboot/cache protocol there, not merely another fresh profile here.
